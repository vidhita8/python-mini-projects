Task 1.2: Git Workflow and Merge Conflict Resolution
Description
This guide explains key Git operations, including:

Forking a repository, cloning it, and creating a pull request.

Managing files with .gitignore and structuring a README.md file.

Simulating and resolving merge conflicts in a collaborative project.

Prerequisites
To follow this guide, you need:

Git installed on your system.

A GitHub account with access to repositories.

A text editor or IDE (such as VS Code or Sublime Text).

How to Use This Guide
1. Cloning a Repository
Go to the repository on GitHub.

Click the Code button and copy the repository URL.

Open a Git client (like GitHub Desktop or Sourcetree).

Click Clone Repository, paste the URL, and select a local folder to save the project.

2. Forking a Repository
Navigate to the repository on GitHub.

Click Fork (top right of the page).

This creates a copy under your GitHub account.

Open GitHub Desktop or another Git client and clone your forked repository.

3. Creating a Pull Request
After making changes, go to your GitHub repository.

Click Pull Requests > New Pull Request.

Select the branch with your changes and compare it with the main branch.

Click Create Pull Request, add a title and description, then submit.

4. Using .gitignore and README.md
.gitignore helps exclude unnecessary files (like log files or dependencies) from being tracked.

A README.md file provides an overview of the project, usage instructions, and author details.

5. Resolving Merge Conflicts
If multiple people edit the same file, Git may highlight a merge conflict.

The conflicting file will show both versions of the changes.

Open the file in a text editor and manually choose which parts to keep.

After resolving, save the file and commit the changes.
